# Implementation decisions

Choices made while building where the PRD/design left room. The PRD's own decision register (D-01..D-21) is in `docs/prd/ui-design-review.md` and is followed as written.

| # | Decision | Why |
|---|---|---|
| 1 | Scope of the first pass is PRD Phases 0+1 as a vertical slice. | Agreed with the product owner; the full plan is ~14.5 weeks. |
| 2 | All 22 tables ship in the first migrations (journal and AI tables included, unused). | PRD 11.2: the slice model, exclusion constraint and timezone rule must land in Phase 1; later phases then add no breaking schema. |
| 3 | Migrations are raw SQL DDL, one statement per `op.execute`. | Reads like the data dictionary; exclusion constraint, triggers and partial indexes are explicit. asyncpg cannot prepare multi-statement strings. |
| 4 | Services commit; a decorator rolls back on any error. | Keeps a half-applied edit from lingering and makes error paths testable with a shared transaction. |
| 5 | Event and task timestamps use `clock_timestamp()`. | `now()` is frozen per transaction, which made same-request events and tasks tie and sort randomly. |
| 6 | Timeline reads `activity_day_slices` for blocks and coverage; today is prorated and never "complete"; future days show no gaps. | One source of truth for every number (D-15). |
| 7 | Coverage `logged` includes unplaced (duration-only) time; gaps are computed from placed time only. | Unplaced time counts toward the 24h rule (D-04) but has no position to draw. |
| 8 | Tag goal status values: `none`, `ok`, `over` (max) and `under`, `met` (min). Range defaults to the current week in the user's timezone. | AC-046 needs `over`; the PRD does not name the others. |
| 9 | Category archive is refused while the latest Ideal version allocates it (`CATEGORY_ALLOCATED`); delete is refused for any allocation. | FR-088. |
| 10 | Category merge leaves the archived source where it was and moves its children to the target. | FR-089; avoids path churn on an archived row. |
| 11 | Tag merge adds the old name as an alias of the target even though the archived source still holds the name. | AC-041; alias-equals-tag-name is only refused for non-merged tags. |
| 12 | Google-only accounts cannot delete their account or change a password until they set one via "Forgot password". | FR-009/FR-012 require re-auth; a fresh-Google-login token flow is deferred. |
| 13 | Export is built in a background task and stored on local disk (`EXPORT_DIR`), downloadable for 24 h. | R2 and the worker arrive later; the API contract (E-16/E-17) is unchanged. |
| 14 | The onboarding Ideal Day is "balanced" (sleep 7h30, deep work 4h30, ...), effective from the day of onboarding. | The PRD names a preset without defining it; it must total exactly 1,440 minutes. |
| 15 | Dev server proxies `/api`; refresh cookie is `Path=/api/v1/auth`, `HttpOnly`, `SameSite=Lax`. | Same-site in dev and with `app.`/`api.` subdomains in production. |
| 16 | "Yesterday is short" nudges only appear once something has been logged. | A new account has nothing to be short of (found while testing in the browser). |
| 17 | Frontend uses npm (not pnpm) and Vite 6 / Vitest 3 pins. | pnpm is not installed here; `@vitejs/plugin-react` 6 needs Vite 8. |
| 18 | The AI worker is a Postgres queue (`FOR UPDATE SKIP LOCKED`, retries 2s/8s/30s, stuck jobs requeued after 5 min) instead of Procrastinate. It runs inside the API process by default (`EMBEDDED_WORKER`) or as `python -m app.workers.run`. | No new dependency or service; the job table already existed; swapping to a library later does not change the API. |
| 19 | `LLM_PROVIDER=auto` uses Anthropic when `ANTHROPIC_API_KEY` is set and a deterministic offline reader otherwise; the UI labels the latter "Demo mode". | The app, tests and CI run without a key; nobody mistakes demo output for model output. |
| 20 | The model only reads language (one forced tool call, schema v1). Times, tags, tasks, overlaps, confidence bands and questions are decided in code. | PRD 4.6: auditable, testable, and a model change cannot move your time. |
| 21 | A bare "9" in a spoken range takes its am/pm from the previous activity's end; a question is asked only when that is ambiguous after an earlier activity. | The first activity of an entry has nothing to jump from, so it never gets a meridiem question. |
| 22 | Server-side speech-to-text is not built. Dictation uses the browser's Web Speech API; unsupported browsers type. | Chosen with the product owner for this pass. |
| 23 | On the review screen only overlap fixes that can work are offered: shortening needs the overlap to touch an edge of the activity. Otherwise: replace the other, or keep as "some time". | The server refuses a trim that would split an activity into two pieces; the UI should not offer it. |
| 24 | Tailwind colour tokens that need an opacity modifier (`bg-bad/10`) are defined with `color-mix(... <alpha-value>)` so they stay CSS variables and dark mode keeps working. | Plain `var()` colours silently dropped the modifier and fell back to browser defaults (found when a highlight rendered bright yellow). |
| 25 | Saving an Ideal template asks for an effective date (today, start of this week, or a chosen date); older versions are kept and past comparisons never change. | FR-111 / M-10. |
| 26 | `unlogged = elapsed - (placed + unplaced)` and coverage counts duration-only time, matching the timeline (decision 7); the PRD table says placed only. | One definition on every screen: the calendar and the dashboard must show the same number. |
| 27 | Week adherence and the week comparison use finished days only (today is excluded); day scope prorates today and is marked provisional. | FR-126 and FR-127. The week payload is therefore never provisional. |
| 28 | Analytics ETags hash the user's `data_revision`, the URL and, for any range that includes today, the current minute. | Today's elapsed time changes without a write, so a revision alone would serve a stale "so far" figure. |
| 29 | The coverage banner picks the latest finished day that has something logged but is short; an untouched day is not "short". | A week you never opened should not nag about each empty day (see decision 16). |
| 30 | Trend granularity `day` allows up to 366 periods (week stays at 52). | The 26-week heatmap needs 182 daily points; the PRD's 52 limit is for weeks. |
| 31 | Work vs personal is a segmented bar, not a donut; the 24h view is a ring because angle is time of day. | Part-to-whole is read by length; a clock is the one place an angle carries meaning. |
| 32 | Seeded demo data is made through the public API (`scripts/seed_demo.py`), paced under the rate limit. | It exercises the same validation as real use and cannot drift from the schema. |
| 33 | Supersedes 22: server-side speech-to-text is built (FR-016, E-27). The browser records (MediaRecorder: WebM/Opus, MP4/AAC or Ogg, 32 kbps, at most 10 min and 10 MB), uploads once to `POST /transcriptions`, and the server returns text and keeps nothing. | Live recognition only exists in Chrome, Edge and Safari; Firefox, Brave, Arc and app shells need another path. Asked for by the product owner. |
| 34 | `STT_PROVIDER=auto` uses OpenAI `gpt-4o-mini-transcribe` when `OPENAI_API_KEY` is set and is otherwise *unavailable*. There is no demo transcriber. `fake` exists for tests and is refused in production. | An invented transcript would look real and end up in someone's journal. The app instead says plainly that server transcription is not set up. |
| 35 | Which path runs follows the existing setting: Automatic prefers live text and falls back to a recording, including when live recognition fails at once with a network or unknown error; Browser only never uploads; Server only always records. The recorder and the upload are checked for real audio by content, not file name, and limited to 20 an hour per user. | Honours "audio never leaves your device" for those who chose it (NFR-05) and keeps the upload endpoint from being a general file sink. |
| 36 | Live recognition treats "no speech heard" as normal and keeps listening; only three silent sessions in a row, or three that end instantly, stop it with a message. | Chrome ends a session after a few quiet seconds; stopping on that looked like the mic switching itself off. |
| 37 | The extraction call uses `tool_choice: auto`, an instruction to call the tool once, `effort: medium`, and one retry when the model answers in plain text. | Current models answer 400 to a forced tool choice (`any` / `tool`). Our own schema validation still decides what is accepted. Found when the first real entries all failed with PROVIDER_ERROR. |
| 38 | Provider rejections are logged server-side with the provider's message (never the journal text), and the review screen explains each job error code. | The earlier generic "Something went wrong" hid a one-line server fix. |
| 39 | After an earlier activity, a spoken time that fits nowhere in the window is read as *later* than the window (flag `after_window`), never as an earlier moment on the previous day. The first thing said can still reach back for last night's sleep. | Entries dictated at 3am that plan the rest of the day put "lunch 12 to 1" on yesterday. |
| 40 | The review screen unticks activities that start after the window ends and says why; a question about an unticked activity does not hold up saving; a line above the cards lists exactly what is stopping Save, with links. | A greyed-out Save with the reason hidden in a tooltip, and plans being saved as if they had happened. |
| 41 | Dropdowns are one design-system component (`ui/Select`), a drop-in for `<select>` (same value, `onChange(e.target.value)` and option/optgroup children) drawn with our tokens, with arrow, Home/End, Enter, Escape and type-to-jump. Date and time inputs stay native. | The operating system's menu ignored the theme and the design. |
| 42 | The day is the default view in Overview and Calendar (`?scope=week` and `?view=week` opt in). Weekly things (tag limits, the Ideal week) stay weekly. | Asked for by the product owner. |
| 43 | "Work outside office hours" is measured by time of day (outside the Settings office hours, and all of a weekend), separate from the PRD's place-based "Work away from the office". Both are shown, labelled. | Work logged at 12am to 2am was not being flagged: it had no location, and the place-based figure ignores time. |
| 44 | Charts follow the design's Hover & Tooltip Spec: the 24h ring widens the hovered arc, fades the rest and shows the entry in its centre (click scrolls to it in the log); grouped columns and meters dim the others to 35%; heatmap, treemap and line points get the ink outline or 35% growth, with click-through to the day or week; tooltips rise 4px over 120ms. | Hover behaviour the design defined was only partly built. |
| 45 | A Work / Personal lens (All, Work, Personal) sits in the header of Overview, Calendar and Ideal, is remembered per browser, and is sent as `lens=` to the timeline, activity list, breakdown and every analytics call. Personal includes Sleep. Coverage stays whole-day under a lens. | Asked for demos: show only work or only personal life with one click. A gap is a gap whichever side you look at, so coverage is not filtered. |
| 46 | Tags show a chosen range (last 7 days by default, this week, last week, last 30 days) and open on the busiest tag. | On a Monday morning "this week" was empty everywhere. |
| 47 | Signing in returns to the `?next=` page instead of always Overview; the Calendar's "short day" banner ignores untouched days (as the Overview already did). | Found while preparing the demo. |
